# 瞄准解算拆分与期望角度规划

日期：2026-10-19
对象：`ros2_layer/node/vision/`（当前单文件节点）+ 新增算法层瞄准解算
现状依据：`vision_node.hpp` 158 行、`vision_node.cpp` 722 行（拆分后实测）、`tracker.cpp` 347 行。

本文只规划"跟踪器选好的那一面 → 云台期望角度"这条链，以及它应该住在哪一层。
不改跟踪算法、不改 EKF、不调参、不动话题名。

---

## 0. 边界

1. **节点是拼装站**：`vision_node.cpp` 只保留订阅、回调、调用顺序；几何解算进算法层，ROS 发布进独立发布器。
2. **算法层不依赖 ROS**：`framework/` 现在不链接 rclcpp，新增的瞄准解算也必须保持这一点。
3. **行为不变**：拆分前后同一输入下的 `yaw / pitch / distance / fire_advice` 必须逐位一致（≤ 1e-9°）。
4. 不引入弹道补偿、枪口偏移、目标速度前馈；这些是后续独立任务。

### 1.4 当前角度是怎么算出来的（必须逐字保留的公式）

输入（全部在 `map` 系）：

```text
p_target  = R_map_camera · p_aim_camera + t_map_camera      （publish_aim 第 386–415 行）
d         = p_target − g_map                               （g_map = 云台原点在世界系的位置）
yaw_deg   = atan2(d.y, d.x) · 180/π
pitch_deg = 90° − atan2(d.z, hypot(d.x, d.y)) · 180/π      （从竖直轴量起，水平 = 90°）
distance  = |p_aim_camera|                                  （相机到目标，不是 |p_target|）
fire      = distance ≤ aim_distance_max_m 且 |pitch − 90°| ≤ aim_fire_angle_deg
```

`p_aim_camera` 来自：

```text
face = tracker.Report().last_face
p_aim_tracking = tracker.Faces()[face].xyz                  （跟踪系）
p_aim_camera   = FrameToCamera(p_aim_tracking, frame)       （相机系）
前提：tracker.Converged() && frame 有值 && face >= 0
       && p_aim_camera.z > 0.1 && |p_aim_camera| ≤ aim_distance_max_m
```

### 1.5 误差预算（为什么这一层值得单独拿出来验）

同一场景日志实测：`pose offset avg=−0.5 ms`，`min=−28 ms`，`max=53.7 ms`；帧率 74.9 Hz，云台转速若按 60°/s：

```text
姿态时间误差 53.7 ms × 60°/s = 3.22°
```

而几何解算本身只受云台位置精度影响，1 cm 位置误差在 1.5 m 处：

```text
atan(0.01 / 1.5) = 0.38°
```

**时间对齐贡献比几何解算大 8.5 倍。** 所以拆分时不能把时间对齐藏进解算里——它必须留在节点层，
由节点决定"这一帧用哪个时刻的姿态"，解算层只吃已经对齐好的数。

## 2. 目标结构

```text
framework/algorithm/vision/aim/
    aim_solver.hpp        纯数据契约：输入、输出、判定阈值
    aim_solver.cpp        公式 1.4 的唯一实现（无 ROS、无 TF、无日志）

ros2_layer/node/vision/
    vision_node.hpp/.cpp      拼装：订阅、参数、回调顺序
    camera_tf.hpp/.cpp        /tf → map←相机（按时间戳入缓存）+ 云台世界位姿
    aim_publisher.hpp/.cpp    取 tracker 结果 → AimSolver → GimbalCmd → 发布
    vision_draw.hpp/.cpp      绘制实测框与预测四面
    vision_log.hpp/.cpp       每秒日志窗口
```

依赖方向（单向，不许回指）：

```text
vision_node ──> aim_publisher ──> aim_solver
     │                │
     ├──> camera_tf   └──> tracker 的只读接口
     ├──> vision_draw
     └──> vision_log
```

`aim_solver` 的输入只有 4 个向量/标量，**不含 tracker、不含 tf2、不含 ROS 时间**：

```cpp
struct AimSolverInput
{
    Eigen::Vector3d aim_camera;      // 瞄准点，相机系，m
    Eigen::Matrix3d map_from_camera; // 相机系 → map
    Eigen::Vector3d camera_in_map;   // 相机原点在 map
    Eigen::Vector3d gimbal_in_map;   // 云台原点在 map
    double fire_angle_deg;           // 开火允许的 pitch 偏差
    double distance_max_m;           // 开火与可视距离上限
};

struct AimSolution
{
    double yaw_deg;
    double pitch_deg;
    double distance_m;
    bool   fire_advice;
};
```

`AimSolver()` 只做 1.4 的式子和输入检查（非有限、`z ≤ 0.1`、水平分量过小），返回 `std::optional<AimSolution>`。

## 3. 分步骤

### 步骤 1：抽 `AimSolver`（零行为变化）

**做什么**：把 1.4 的公式原样搬进 `framework/algorithm/vision/aim/aim_solver.cpp`，在 `framework/CMakeLists.txt`
的 `framework_vision` 源文件列表里加一行。

**落点**：
- 新建 `framework/algorithm/vision/aim/aim_solver.hpp` / `.cpp`
- `framework/CMakeLists.txt:26-35` 源文件列表
- `vision_node.cpp` 的 `publish_aim` 改为调 `AimSolver`，节点只保留 TF 查询和发布

**公式**：同 1.4，不重排、不合并项，保持 `atan2(d.z, hypot(d.x, d.y))` 而不是 `asin(d.z/|d|)`
（后者在 `|d|` 很小时会放大浮点误差）。

**验收数字**：
- `rg -n "rclcpp|sensor_msgs|tf2|ros2" framework/algorithm/vision/aim` = **0**
- 用同一组实测输入（日志里的 `target_map=(−2.936,−0.454,0.302)`、`gimbal_world=(−3.888,−1.595,0.291)`）
  跑新旧两条实现，`yaw`/`pitch` 差 ≤ **1e-9°**，`distance` 差 ≤ **1e-12 m**。
- 跑同一场景 60 s，`aim cmd` 行的 `yaw / pitch / dist / fire` 与拆分前逐行一致。
- 单次调用耗时 ≤ **1 µs**（当前整帧 `ms=5.54`，占比 < 0.02%）。

**失败分叉**：
- 角度差在 1e-9° 量级以外 → 检查是否把 `hypot` 换成 `norm`、或把度/弧度转换挪了位置。
- 目标在相机背后时行为不同 → 检查 `z ≤ 0.1` 的检查是否仍在解算前。

### 步骤 2：抽 `AimPublisher`（零行为变化）

**做什么**：把 `publish_aim` 里除角解算外的部分（取 tracker 面、查 TF、组 `GimbalCmd`、
固定角标定模式、`distance = −1` 的空指令）收进 `AimPublisher`。

**落点**：
- 新建 `ros2_layer/node/vision/aim_publisher.hpp/.cpp`
- 构造函数接收：参数（话题、`aim_frame`、`camera_frame`、阈值、固定角）、`tf2_ros::Buffer&`、
  发给 tracker 的只读引用/回调
- `vision_node.cpp` 里 `publish_aim(msg.header)` 改成 `aim_publisher_->Publish(msg.header)`

**接口约定**（消费方语义先写在头文件上）：

```text
输入：图像 header（时间戳用于查 TF）、tracker 的 Converged()/Faces()/Report().last_face、当帧 frame_
输出：/rm_gimbal/cmd 的 yaw/pitch/distance/fire_advice
失败：无可瞄面 / TF 查不到 / 点不在相机前方 → 发 distance = −1.0、fire_advice = false
```

**验收数字**：
- `vision_node.cpp` 行数从 **722** 降到 ≤ **600**（本步只搬 125 行 + 少量成员）。
- `rg -n "atan2" ros2_layer/node/vision/vision_node.cpp` = **0**（角度公式只剩一份）。
- 与步骤 1 同样的 60 s 场景，`/rm_gimbal/cmd` 逐条一致（时间戳、四个字段）。
- TF 查不到时仍按原逻辑先按图像时间戳查、再退到最新一帧，`WARN_THROTTLE` 文案不变。

**失败分叉**：
- 出现 `distance = −1` 的频率变高 → 先查 `AimPublisher` 里 `Converged()` 的调用时刻是否被挪到了
  `ProcessFrame` 之前。
- TF 查询抛 `ExtrapolationException` 次数变多 → 检查是否误用了墙钟而不是消息时间戳。

### 步骤 3：抽 `CameraTf`（行为不变，收口两段手写链）

**做什么**：把 `on_tf` 里的两段遍历（云台链、相机链）收进 `camera_tf.cpp`，对外只暴露两个查询：

```text
PoseSample CameraPoseAt(double stamp, double hold_s)   // map←相机，带插值
bool        GimbalPoseAt(double stamp, ...)            // 云台世界位姿（当前只用到位置）
```

**落点**：
- 新建 `ros2_layer/node/vision/camera_tf.hpp/.cpp`
- 删除 `gimbal_rotation_`、`armor_world_snapshot_`（1.3 实测无人读）
- `vision_node.cpp` 的 `on_tf` 只剩一行转调

**验收数字**：
- `vision_node.cpp` 行数 ≤ **500**。
- 同一段录制的 `/tf` 重放，`camera_pose_.At()` 的返回值与拆分前逐位一致（四元数与平移 ≤ 1e-12）。
- `rg -n "armor_world_snapshot_|gimbal_rotation_" ros2_layer` = **0**。

**失败分叉**：
- 位姿插值结果不一致 → 检查样本入队时刻是否仍取"相机链第一段 TF 的 stamp"。
- 云台位置缺失导致自瞄不发射 → 检查 `gimbal_link → map` 的遍历方向是否与原来一致（子向上走）。

### 步骤 4：抽绘制与日志（可后置）

**做什么**：`draw_*`（73 行）与 `log_window`（109 行）各自成文件，节点只调一行。

**落点**：`vision_draw.hpp/.cpp`、`vision_log.hpp/.cpp`；日志窗口的成员计数器随代码一起搬走。

**验收数字**：
- `vision_node.cpp` ≤ **300**。
- 每秒日志行数与内容完全一致（逐行 diff 空）。
- 绘制后的 `/vision/debug_image` 与原实现逐像素一致（同一帧输入）。

**失败分叉**：日志少行 → 检查窗口计数是否被搬走后重复清零；绘制框位置变了 → 检查
`tracker_config_.vehicle.armor_pitch_rad` 的来源是否仍与跟踪器同一份配置。

### 步骤 5：补测试（新增，不改行为）

**做什么**：把 1.4 的三个公式写成 `project/thread/test/trd_test.cpp` 里的当前测试：
输入 3 组固定向量（正前方、侧方、下方），断言角度与手算值一致。

**验收数字**：
- 正前方 `d=(1,0,0)` → `yaw=0.000°`、`pitch=90.000°`、`distance=1.000 m`

## 4. 顺序为什么不能换

1. **先解算后发布**：解算没有 ROS 依赖，用纯函数验收最便宜；先拆发布层会把公式和 ROS 混在一起，
   没法做 1e-9° 的对照。
2. **先发布后 TF**：`AimPublisher` 要调用 `CameraPoseAt`，但当前接口不变；先抽发布能把"谁在什么时刻取姿态"
   固定下来，再动 TF 才不会把时间对齐一起改掉（1.5 已量化：时间误差是几何误差的 8.5 倍）。
3. **绘制/日志最后**：它们只读状态，不参与解算；先动它们只会让 diff 变大。
4. **测试最后**：为了验证前面每一步都没有改变数值，测试要在公式定版之后写；提前写会把中间版本固化。

## 5. 失败回退表

| 症状 | 先查 | 再查 | 最后才查 |
| --- | --- | --- | --- |
| 拆分后 `yaw/pitch` 不一致 | 解算输入的顺序（相机系 / map 系） | 度/弧度转换位置 | 浮点重排（`hypot` vs `norm`） |
| `distance` 变了 | 是否用了 `|p_target|` | 是否在 map 系求模长 | 相机原点补偿 |
| 自瞄不出目标 | `Converged()` 调用时刻 | `last_face` 是否为 −1 | `frame_` 是否为空 |
| TF 查询失败变多 | 查询用的时间戳 | 缓存是否仍按图像时刻插值 | `hold_s` 参数 |
| 日志少行/多行 | 窗口计数器归属 | `log_window` 的调用点 | 每秒清零时机 |
| 画面框错位 | `armor_pitch_rad` 来源 | `tracker_->Size()` 与实测尺寸 | `frame_` 是否当帧更新 |

## 6. 本文不做的事

- 不加弹道下坠、飞行时间、枪口偏移补偿。
- 不加目标速度前馈（当前瞄准的是 `Faces()[last_face]` 的当前估计位置）。
- 不改 `last_face` 的选择策略（三项加权已在跟踪器内完成）。
- 不改 TF 的坐标系约定（`map ← camera`、`map ← gimbal_link`）。
- 不动 `/rm_gimbal/cmd` 的字段语义：`yaw` 世界系绝对角、`pitch` 从竖直轴量起、`distance = −1` 表示无目标。
