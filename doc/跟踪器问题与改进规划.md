# 跟踪器问题与改进规划

日期：2026-10-17  
对象：`framework/algorithm/vision/track/`、`framework/algorithm/vision/pose/`、`ros2_layer/node/vision/`  
参考：`temp/Dust_infantry_vision-main/tasks/auto_aim/`（唯一实现基准）  
仿真侧数字来自 `third_party/bevy_robomaster_simulator-master`。

本文只写现状实测、病灶依据与改造方案，不含代码修改。行号按当前源码。

---

## 0. 硬约束

1. **实现严格按 `temp/Dust_infantry_vision-main` 对齐。**结构、函数划分、状态机、观测与关联、参数名都以参考为准；参考里没有的做法不加，参考里有的不省。本工程与参考的差异只允许来自**平台**（ROS 节点、TF 代替 IMU 四元数、TensorRT 检测器），不允许来自算法选择。
2. **只做单跟踪器。**参考的 `Tracker` 只持有一个 `Target`（`tracker.hpp:90`），每次 `track()` 返回 `std::list<Target>` 里最多一个元素（`tracker.cpp:220`）。本工程当前是按编号分槽的 `MultiTargetTracker`（`multi_target.hpp:38-45`），本次改造**删掉槽位这一层**，改成参考一样的 `Tracker + Target`。多目标/多槽等参考项目本身跑通、且本工程确实需要时再做。
3. **当前目标是 `Three + Small` 四面车。**参考对普通车用 `armor_num=4`（`tracker.cpp:390-391`），与本工程一致。两面/三面分支（平衡步兵、前哨站、基地）按参考代码结构保留判断入口，但当前不投入验证。

## 1. 结论

按实测能解释的量排序：

1. **观测噪声与像素信息不匹配。** `armor_tracker.cpp:378-383` 的 R 是参考旧版公式的硬编码版本，`point_sigma_px`、`sigma_distance_scale` 读了从未参与计算。按本机内参，x/y 噪声方差比像素真实值大 **106 倍**，z 约 **200 倍**（§3.3）。观测几乎不修正中心与半径。
2. **观测向量本身和参考不同。**参考观测是 `[yaw, pitch, distance, armor_yaw]`（`target.cpp:295-330`，`math_tools.cpp:103-110`），本工程是 `[x, y, z, a]`（`armor_tracker.cpp:328-329`）。参考的 R 公式、NIS 自由度、门限都建立在前者上；照搬数字但换了观测量，是当前参数失效的根因之一。
3. **角度残差没有周期归一化。**参考 `update_ypda` 给 EKF 传了 `z_subtract`，对 yaw/pitch/armor_yaw 都做 `limit_rad`（`target.cpp:311-317`）。本工程 `ekf.hpp` 提供了 `set_subtract`，`armor_tracker.cpp` 从未调用。
4. **相机系预测把云台转动当成目标运动。**参考每次 `track()` 之前都用当帧姿态刷新 `solver.set_R_gimbal2world(q)`（`auto_aim_runtime.cpp:547`），EKF 状态在世界系。本工程没有这一步。
5. **面关联只剩宽位置门。**`face_gate_rad=0.6`、`position_gate_m=1.5`（`multi_target.hpp:69`）。1.5 m 在 2 m 处折合 978 px；参考的四门是 100 px / 140 px / 0.8 rad / 0.6（`tracker.cpp:442-486`，`standard3.yaml:55-60`）。
6. **发散判据被钳制掩盖，但参考不这么做。**参考的 `apply_state_limits` 只在**图像角点更新成功时**才钳 r/r+l（`target.cpp:257-261`、`419-431`），`diverged()` 用 `(0, 0.8)`（`target.cpp:468-478`）。本工程每帧都钳进 `[0.05, 0.50]` 再用同一区间判发散，永远判不出来。
7. **没有图像角点观测。**参考默认先走 8 维像素观测，失败才回退 PnP（`target.cpp:255-261`、`352-414`）。本工程只有 PnP。
8. **单槽/多槽不是当前问题。**日志显示当前只有一个编号进入跟踪；参考的单目标结构能完整表达现在的工况。

改造顺序按参考的依赖关系：**单目标骨架 → 世界系与 ypd 观测 → PnP 噪声传播 → yaw 优化 → 像素四门 → 8 维角点观测 → NIS/状态机判据 → 参数**。

## 2. 事实基线

### 2.1 平台

| 项 | 当前值 | 来源 |
|---|---|---|
| 图像 | 1440×1080，`rgb8` → `bgr8` | `src/capture.rs:166-167`，`camera_node.hpp:97-119` |
| 内参 | `fov_y=45°`，`fx=fy=1303.6 px`，`cx=720`，`cy=540`，无畸变 | `config.toml:105`，`src/capture.rs:145-164` |
| 图像 frame | `camera_optical_frame` | `src/ros2/capture.rs:53` |
| TF 链 | `map → odom → gimbal_link → camera_link → camera_optical_frame` | `src/ros2/plugin.rs:205-216` |
| 跟踪槽 | `kTargetLabels = { ArmorLabel::Three }` | `multi_target.hpp:38-40` |

1 px 在距离 d 处对应 `d / 1303.6` m：d=2 m 时 1.53 mm，d=4 m 时 3.07 mm。

### 2.2 日志里实际是什么

```text
det color=blue label=2 size=0   -> Three + Small，进入 Three 槽
det color=blue label=0 size=1   -> One + Large，不进槽
```

`Three` 的枚举值是 2，`Small/Large` 是 0/1（`armor_types.hpp:32-56`），标签与尺寸由同一个 `raw_label_id` 解码（`model_decode.cpp:41-79`），所以 `Three + Large` 在当前解码路径不可能出现。日志里的其余 `observed`（2.5~2.8 m）是 `One + Large` 那辆车，不是离群点。

`detections=N（进槽的敌方颜色）` 这句措辞是错的：它统计的是敌方颜色检测数，不是进槽数。

### 2.3 当前 R 与物理噪声

`armor_tracker.cpp:378-383`：

```text
R_xx = R_yy = 4e-3
R_zz = log(|delta_angle| + 1) + 1
R_aa = log(|observed_pitch| + 1) / 200 + 1e-2
```

x/y 的 `4e-3` 对应 σ = 63.2 mm。按 `point_sigma_px=4`，2 m 处 σ_x = σ_y = `4×2/1303.6 = 6.1 mm`，方差 `3.8e-5`；当前是 **106 倍**。

z 由板的横向尺寸 W 决定，`σ_z = d²·σ_px/(f·W)`。小装甲 W=0.135 m、d=2 m、σ_px=4：

```text
σ_z = 4×4/(1303.6×0.135) = 0.0909 m  -> 方差 8.3e-3
```

当前 `delta_angle = observed_yaw − center_yaw`，其中 `center_yaw = atan2(x, z)`（从 +z 量）、`observed_yaw = atan2(n_z, n_x)`（从 +x 量），两者差约 90°，日志里 |Δ| = 60°~115°，得 `R_zz ≈ 1.7~2.1`，比物理值大 **~200 倍**。

角度：`σ_a = 2·d·σ_px/(f·W) = 0.091 rad`，方差 `8.3e-3`，当前 `R_aa ≈ 1.01e-2`，量级**基本正确**。

| 分量 | 当前 R | 物理推导（d=2 m，σ=4 px） | 倍数 |
|---|---:|---:|---:|
| x | 4.0e-3 | 3.8e-5 | 106 |
| y | 4.0e-3 | 3.8e-5 | 106 |
| z | 1.7~2.1 | 8.3e-3 | ~220 |
| a | 1.01e-2 | 8.3e-3 | 1.2 |

另有一处与参考的偏差：参考回退公式的第 4 项是 `log(|distance|+1)/200 + 1e-2`（`target.cpp` 的 `armor.ypd_in_world[2]` 是距离），本工程写成了 `observed_pitch`。

### 2.4 日志证据

一次约 60 s 运行（fps 70~78，`ms` 5.9~6.5，`age` 35~52 ms）：

- 半径在两端来回：`0.415 → 0.136 → 0.050 → 0.247 → 0.499 → 0.500 → 0.050 → ...`
- `P_rr` 稳定在 0.002~0.005（σ=45~70 mm），而 r 在 0.05~0.50 之间跳：t=126.98 `r=0.136, P_rr=0.0061`；t=127.99 `r=0.050, P_rr=0.0052`。
- 面 1/3 长期未更新：`l=0.0000`、`h=-0.0220` 数十秒不动，`P_l` 0.0061→0.0727、`P_h` 0.0193→0.0696。约 40 s 内 `P_l` 增 0.0666；`Q_ll = 1.9e-5/帧 × 73 帧/s × 40 s = 0.056`，与“完全无观测”一致。
- t=1158.28 两块 Three 板出现：`P_l → 0.00707`、`P_h → 0.00048`，面 1 确实被更新。
- 同帧观测板心：

  ```text
  observed (-0.174, 0.025, 1.628)
  observed ( 0.105, 0.008, 1.624)
  ```

  弦长 `√(0.279² + 0.017² + 0.004²) = 0.280 m`。四面车相邻面弦长为 `√(r² + (r+l)²)`，对称车为 `r√2`，故 `r_true = 0.198 m`。同一帧滤波给 `r=0.0822`、`l=0.2340`，预测弦长 `√(r²+(r+l)²) = 0.327 m`，差 47 mm。47 mm 在当前 R_xx（σ=63 mm）下只有 0.75σ，滤波器不动；按物理噪声（σ=6.1 mm）是 7.7σ。
- 半径误差 0.3 m 使对侧面位置错 0.6 m，2 m 处折合 `0.6×1303.6/2 = 391 px`。黄框大幅漂移是半径误差的放大，不是“多画了面”。

### 2.5 状态机与关联的实际表现

- `state=tracking active=1 converged=1 updates` 持续增长，`losses`/`gate` 缓慢增加：观测基本都被接受。
- `Diverged()` 恒 false（§1 第 6 条），状态机不会因半径发散回 `lost`。
- 单板帧占绝大多数；双板帧只在目标约 45° 朝向相机时出现，是约束 r/l 的唯一时机。

## 3. 参考项目的精确行为

以下全部从 `temp/Dust_infantry_vision-main` 读出，作为本工程的对齐清单。

### 3.1 结构

| 参考 | 位置 | 说明 |
|---|---|---|
| `class Tracker` 持有一个 `Target target_` | `tracker.hpp:90` | 唯一目标；没有槽位数组 |
| `track()` 返回 `std::list<Target>` | `tracker.cpp:220` | 只装 `{target_}` 或空 |
| `Target` 11 维状态 | `target.cpp:40-45` | `[x vx y vy z vz a w r l h]`，**z 竖直** |
| `Solver` 维护 `R_gimbal2world` | `solver.cpp:47-68` | 每次 `track()` 前由当帧姿态刷新 |
| `Target` 与 `Tracker` 分工 | `target.hpp` / `tracker.cpp` | Target 管 EKF；Tracker 管选板、状态机、关联 |

### 3.2 `Tracker::track()` 的顺序（`tracker.cpp:153-221`）

```text
加锁；last_update_real_observation_ = false
dt = t − last_timestamp_；last_timestamp_ = t
dt > 0.3 s 且非 lost  ->  warn，state_ = lost
按颜色过滤（颜色来自 YAML enemy_color；函数形参 use_enemy_color 未使用）
前哨站顶部板过滤（当前目标不涉及）
按到图像中心的距离升序排序（中心写死 1440/2, 1080/2）
按 priority 升序排序（当前运行路径没有 Decider，priority 全是默认 fifth，这一步实际是稳定排序）
lost -> set_target(armors, t)；其它 -> update_target(armors, t)
有真实观测 -> last_observed_timestamp_ = t
state_machine(found)
diverged() -> state_ = lost，返回空
最近 100 次更新里 NIS 失败 ≥ 80 次 -> state_ = lost，返回空
lost -> 返回空；否则返回 {target_}
```

### 3.3 状态机（`tracker.cpp:308-359`）

```text
lost:       found -> detecting，detect_count_ = 1
detecting:  found -> detect_count_++，达到 min_detect_count_ -> tracking
            !found -> detect_count_ = 0，state_ = lost
tracking:   !found -> temp_lost，temp_lost_count_ = 1
temp_lost:  found -> tracking
            !found -> temp_lost_count_++，超过 max_temp_lost_count_ -> lost
```

`min_detect_count=5`、`max_temp_lost_count=25`（`standard3.yaml`）。前哨站单独用 75。

### 3.4 建目标（`tracker.cpp:361-396`）

取排序后的 `armors.front()`，先 `solver_.solve(armor)`，再按类型选参数：

| 类型 | radius | armor_num | P0 对角 |
|---|---:|---:|---|
| 平衡步兵（big + 3/4/5） | 0.2 | 2 | `{1,64,1,64,1,64,0.4,100,0.5,0.5,1}` |
| 前哨站 | 0.2765 | 3 | `{1,64,1,64,1,81,0.4,100,1e-4,0,1}`，另设 `omega=0.5` |
| 基地 | 0.3205 | 3 | `{1,64,1,64,1,64,0.4,100,1e-4,0,0}` |
| 其它（含当前 Three+Small） | 0.2 | 4 | `{1,64,1,64,1,64,0.4,100,1,1,1}` |

`Target` 构造（`target.cpp:14-56`）：

```text
center_x = xyz[0] + r·cos(ypr[0])
center_y = xyz[1] + r·sin(ypr[0])
center_z = xyz[2]
x0 = {center_x, 0, center_y, 0, center_z, 0, ypr[0], 0, r, 0, 0}
```

### 3.5 更新目标（`tracker.cpp:398-558`）

```text
先 target_.predict(t)                    // 推进到本帧
候选 = armors 里 name 与 type 都与 target_ 相同的
候选为空 -> false（前哨站有 ≤10 帧的间隙预测特例，当前不涉及）
对每个候选 × 每个预测面：
    predicted = solver.reproject_armor(面中心, 面 yaw, armor_type, name)
    cost = quad_cost(predicted, 候选四点)
贪心配对：每次取全局最小 cost，观测与预测面各用一次
每个匹配项：solver_.solve(armor)，再 target_.update(armor, 面号, &solver, image_sigma, pnp_sigma, angle_prior)
found = 匹配数 > 0
```

`quad_cost`（`tracker.cpp:442-486`）四个门同时满足才有效：

```text
center_error          = |预测中心 − 检测中心|                  ≤ 100 px
corner_error          = 四角平均距离                            ≤ 140 px
angle_error           = 四条边方向角差之和                      ≤ 0.8 rad
perimeter_ratio_error = |预测周长 − 检测周长| / 预测周长        ≤ 0.6
cost = 四项分别除以各自门限后相加
```

参考的匹配**不做法向角门、不做法向角匹配**；面序完全由像素轮廓代价决定。

### 3.6 `Target::update()`（`target.cpp:245-330`）

```text
update_count_++
先试 8 维图像观测：solver 存在且 image_point_sigma_px > 0 时
    update_image_points(...)；失败则回退 update_ypda(...)
仅当图像观测成功时调用 apply_state_limits(id)
```

**ypda 观测**（`target.cpp:295-330`）：

```text
z = [yaw, pitch, distance, armor_yaw]        // 世界系，xyz2ypd
h(x) 同定义
H = h_jacobian(x, id)
R: 优先 ypda_measurement_covariance(armor, pnp_sigma, angle_prior)；
   失败回退 diag{4e-3, 4e-3, log(|Δangle|+1)+1, log(|distance|+1)/200 + 1e-2}
z_subtract: yaw/pitch/armor_yaw 都做 limit_rad
```

**图像观测**（`target.cpp:352-414`）：

```text
z = 四点 x/y（8 维）
h(x) = 由状态推面中心与 yaw，经 solver.reproject_armor 投回像素
H: 仅对 x, y, z, a, r, l, h 做中心差分，步长平移 1e-3 m、角度 1e-3 rad
R = σ_px² · I(8×8)
```

**测量噪声传播**（`solver.cpp:354-430`）：

```text
位姿扰动 ξ = [δt(3), δθ(3)]，绕装甲板自身轴右乘
平移步长 1e-4 m，旋转步长 1e-5 rad
G  (8×6) = d(像素四点)/dξ
Jz (4×6) = d(yaw, pitch, distance, armor_yaw)/dξ
信息 = GᵀG / σ_px² + 先验
先验：平移 1/10²，旋转 1/angle_prior²（默认 angle_prior = 0.15 rad）
R = Jz · 信息⁻¹ · Jzᵀ，再做对称化
```

**钳制与发散**：

```text
apply_state_limits（target.cpp:419-431）：
    仅 armor_num == 4 时 r ← clamp(r, 0.05, 0.50)，r+l 同样钳
diverged（target.cpp:468-478）：
    r ∈ (0, 0.8) 且 r+l ∈ (0, 0.8) 之外 -> true
convergened（target.cpp:480-492）：
    普通目标 update_count > 3 且 !diverged
```

注意：钳制只在图像观测成功后执行；ypda 路径不钳，所以 `diverged()` 的 `(0, 0.8)` 仍有意义。本工程“每帧都钳 + 用同一区间判发散”是自相矛盾的。

### 3.7 世界系与 ypd

```text
xyz2ypd（math_tools.cpp:103-110）：
    yaw      = atan2(y, x)
    pitch    = atan2(z, sqrt(x² + y²))
    distance = |xyz|
```

z 竖直。`ArmorCenter`（`target.cpp:485-500`）：

```text
angle = limit_rad(a + id·2π/armor_num)
r_id  = (armor_num == 4 && (id == 1 || id == 3)) ? r + l : r
x = cx − r_id·cos(angle)
y = cy − r_id·sin(angle)
z = (id == 1 || id == 3) ? cz + h : cz
```

### 3.8 PnP 与 yaw 优化（`solver.cpp:76-115`、`233-258`）

- 物点：`{0, ±W/2, ±L/2}`，W 小 0.135 / 大 0.230，L 0.056（`solver.cpp:12-27`）。
- `solvePnP(..., cv::SOLVEPNP_IPPE)`，`R_armor2camera` 与 `t_armor2camera` 存进 Armor。
- `optimize_yaw`：以相机光轴在世界的 yaw 为中心，±70°、步长 1°，取四角像素误差和最小的 yaw；`yaw_raw` 保存原值。普通目标的重投影用固定 `pitch = +15°`，前哨站 `−15°`。
- `reproject_armor` 的位姿只能是 `(world_xyz, yaw) + 固定 pitch`，表达不了 tilt/roll。

### 3.9 可视化（`visualization/vision_overlay.cpp`）

- 检测到的板：青色 `{255,255,0}` 四点轮廓。
- 跟踪目标的**全部预测面**：绿色 `{0,255,0}`，遍历 `armor_xyza_list()`，不做可见性筛选。
- 自瞄板（planner 给出且有效）：红色。
- 左上角 `State: <state>` 文本，颜色随状态；白色十字准星（写死 720,540）。

所以“黄框/预测面”本身不是本工程的发明，参考也画；漂移的根因仍然是状态估计。

## 4. 与参考的逐项差异

| 项 | 参考 | 当前工程 | 处理 |
|---|---|---|---|
| 跟踪器结构 | `Tracker` + 单个 `Target` | `MultiTargetTracker` + 按编号分槽 | **改成单目标，删槽位** |
| 状态机 | lost/detecting/tracking/temp_lost，在 `tracker.cpp` | 在 `multi_target.cpp`，无 NIS 判丢 | 移植到单 `Tracker` 并补齐 NIS |
| 目标选择 | 排序后取 `front()`（图像中心最近；priority 在无 Decider 时不起作用） | 按编号分派到固定槽 | 改成“排序取首个” |
| 关联 | 像素四门 + 贪心 | 法向角差 + 1.5 m 位置门 | 改为四门 |
| 观测 | 先 8 维像素、再 ypda 回退 | 仅 `(x,y,z,a)` 直接观测 | 改为 ypd + 8 维 |
| 坐标系 | 世界系（`R_gimbal2world`） | 相机系 | 改为世界系 |
| R | 像素传播 + 位姿先验 | 硬编码对角 | 改为传播 |
| 角度残差 | `z_subtract` 归一化 | 无 | 补上 |
| 钳制/发散 | 只在图像更新后钳；diverged `(0,0.8)` | 每帧钳；diverged 同区间 | 按参考改 |
| 图像观测开关 | `image_point_sigma_px > 0` | 无 | 按参考加参数 |
| 大 dt | > 0.3 s 判 lost | 无 | 补上 |
| `fixed_r_` | 只在构造时赋值，运行期未使用 | — | 不实现 |

## 5. 分阶段改造

每阶段结束时用同一套 60 s 场景与同一组日志指标验收；不跨阶段调参。

共享日志字段：

```text
state / detect_count / temp_lost_count
x[11] 全量                        (x, vx, y, vy, z, vz, a, w, r, l, h)
obs_yaw_pitch_dist_armor         ypda 观测量
pred_face[id] 重投影四点         与检测四点的 center/corner/angle/perimeter 四项误差
cost / matched_face              本帧配对结果
nis / nis_fail_recent            最近 100 次失败数
proj_err_px                      图像观测四角平均误差或 PnP 四角平均误差
r_ref / chord_res                双板帧弦长反算半径与残差
R_diag                           本次更新用的 R 对角
```

### 阶段 0：单目标骨架（对齐 `Tracker + Target`）

**做什么**

- 删除 `MultiTargetTracker` 的槽位表与逐槽数组，改为一个 `Tracker`：
  - 成员：`Target target_`、`TrackerState state_`、`detect_count_`、`temp_lost_count_`、`min_detect_count_`、`max_temp_lost_count_`、`last_timestamp_`、`last_update_real_observation_`。

- `Target` 由现有 `ArmorTracker` 改名/收敛而来，去掉“槽”语义；日志访问器保留。
- 状态机逐条照 `tracker.cpp:308-359`，参数 `min_detect_count=5`、`max_temp_lost_count=25` 进 YAML。
- 大 dt：`dt > 0.3` 且非 lost → `lost`。
- 目标选择：先按到图像中心距离升序，再按 priority 升序（当前没有 Decider，priority 全为默认值；保留排序是为了结构一致），取 `front()` 建目标；更新时按 `name + type` 过滤候选。
- `vision_node` 里删除 `kMaxTargets`、`Reports()` 多槽循环、`SelectAimPointCamera()` 的槽循环；只保留一个目标。

**落点**

- `framework/algorithm/vision/track/multi_target.hpp/.cpp` → 改成 `tracker.hpp/.cpp`（`Tracker`），`kTargetLabels` 删除。
- `framework/algorithm/vision/track/armor_tracker.hpp/.cpp` → `target.hpp/.cpp`（`Target`）。
- `framework/algorithm/vision/track/*` 的 CMake 登记、include 全部同步。
- `ros2_layer/node/vision/vision_node.hpp`：日志、绘制、自瞄都改单目标。
- `project/params/vision.yaml`：`min_detect_count`、`max_temp_lost_count` 加入。

**验收**

- 日志里只有一份 `target` 块，不出现 `slot=`。
- 目标在视野内时 `state` 按 `lost → detecting → tracking` 转移，`detect_count` 到 5 才进 tracking。
- 目标离开 25 帧内回到 `lost`；`dt > 0.3 s` 的帧里 `state` 直接变 `lost`。
- 自瞄只在 `tracking` 时发布目标。

**失败分叉**

- 状态机不前进 → 查 `found` 的返回值是否来自“有匹配”，而不是“有检测”。

### 阶段 1：世界系与 ypd 观测

**做什么**

把状态、观测、预测面全部搬到世界系；观测向量改成参考的 `[yaw, pitch, distance, armor_yaw]`，竖直轴为 z。

**落点**

- `armor_pose.hpp/.cpp`（后续改名为 `solver.hpp/.cpp` 对应参考分工，可选）：
  - 新增世界系变换 `R_gimbal2world` / `t`，由调用方每帧传入。
  - `ArmorRotation(yaw, pitch)` 改成参考形式：

    ```text
    R_armor2world = [cos y·cos p, −sin y, cos y·sin p
                     sin y·cos p,  cos y, sin y·sin p
                     −sin p,       0,     cos p      ]
    ```

  - 新增 `ReprojectArmor(world_xyz, yaw, size, pitch)`，用当前 `R_gimbal2world` 反投到像素。
  - 新增 `XyzToYpd` / `YpdJacobian`（照 `math_tools.cpp:103-136`）。
- `target.cpp`：
  - `ArmorCenter` 改成 `(cx − r cos a, cy − r sin a, cz [+h])`。
  - `Initialize` 用 `ypr_in_world[0]` 与 `r` 反推中心。
  - `Observe` 返回 `[yaw, pitch, distance, armor_yaw]`。
  - EKF 的 `set_subtract` 对 yaw/pitch/armor_yaw 做 `limit_rad`。
- `ros2_layer/node/vision/vision_node.hpp`：
  - 每帧查 `map ← camera_optical_frame` TF，构造 `R_gimbal2world`；在 `track()` 之前传入。
  - TF 失败：只预测、不更新，并计数。
  - 绘制时用同一姿态反投。
- `vision.yaml`：`aim_frame` 继续用 `map`。

**算法**

```text
p_world = R_map_cam · p_cam + t_map_cam
R_armor2world → yaw = atan2(R(1,0), R(0,0))
ypd = (atan2(y, x), atan2(z, hypot(x, y)), |xyz|)
ArmorCenter(a, id) = (cx − r_id·cos a, cy − r_id·sin a, cz + h_id)
```

`R_map_cam` 的旋转即参考的 `R_gimbal2world · R_camera2gimbal`。本工程外参默认单位阵，先用 TF 的旋转；将来标定出相机→云台外参后乘进去。

**验收**

- 静止目标、云台水平转 ±30°：世界系中心 10 s 内标准差 < 0.05 m（同条件下相机系坐标会变约 1.0 m）。
- 转动前后 `proj_err_px` 差异 < 30 px。
- `R_gimbal2world` 与仿真 TF 的旋转矩阵逐元素差 < 1e-3（用一帧 dump 核对）。
- 60 s 内 TF 失败率 < 1%。

**失败分叉**

- 世界中心随云台同频 → TF 方向或时间戳。
- 预测面上下颠倒 → 竖直轴仍是 y，或 `ArmorRotation` 的 pitch 符号。
- 面序差 90° → 角度没有用 `atan2(R(1,0), R(0,0))`。

### 阶段 2：PnP 测量噪声传播（对齐 `ypda_measurement_covariance`）

**做什么**

用参考的一阶传播替换硬编码 R；补上 `pnp_point_sigma_px` 与 `pnp_angle_prior_rad` 两个参数。

**落点**

- `armor_pose.cpp`：新增 `YpdaMeasurementCovariance(R_armor2camera, t_armor2camera, size, R_gimbal2world, sigma_px, angle_prior)`，逐行照 `solver.cpp:354-430`。
- `target.cpp`：`Update()` 的 ypda 路径使用该协方差；失败回退参考公式（`log(|distance|+1)/200 + 1e-2`，不是 pitch）。
- `vision_node.hpp` / `vision.yaml`：新增 `pnp_point_sigma_px`（参考默认 8.0）、`pnp_angle_prior_rad`（参考默认 0.15），删除 `sigma_distance_scale`。

**算法**

```text
ξ = [δt(3), δθ(3)]，G = d(uv)/dξ，Jz = d(ypd, armor_yaw)/dξ
信息 = GᵀG/σ² + diag(1/10² · I3, 1/prior² · I3)
R = Jz · 信息⁻¹ · Jzᵀ，对称化
```

理论量级（d=2 m、σ=4 px、小装甲）：`σ_yaw = σ_x/d = 3.05e-3 rad`、`σ_pitch = σ_y/d = 3.05e-3 rad`、`σ_dist = 6.1 mm`、`σ_armor_yaw = 2dσ/(fW) = 0.091 rad`。ypd 三个分量的方差比当前 `[x,y,z]` 公式小 2~5 个数量级，深度与方位直接由像素误差决定。

**验收**

- 正视、d=2 m 的一帧：`R_diag` 与上表相差 < 30%。
- 双板帧 `chord_res` 从实测 47 mm 降到 < 20 mm；`r` 向 `r_ref=0.198 m` 移动。
- 单板持续可见 10 s：r 不单向漂到边界。
- 改 `pnp_point_sigma_px` 4→8，R 四个对角同比例 ×4。

**失败分叉**

- R 差一个数量级 → 扰动步长、`G` 的像素是否带畸变（仿真为 0，实机不为 0）。
- `chord_res` 仍大 → 先看两块板是否被配对到不同面（阶段 4）。
- r 仍贴边界 → 单板不可观，进阶段 6，不回头调 Q。

### 阶段 3：PnP 法向 yaw 优化

**做什么**

照 `solver.cpp:233-258` 在 ±70° 内按四角重投影误差搜 yaw。

**落点**

- `armor_pose.cpp`：`OptimizeYaw(pose/world_xyz, corners, size, R_gimbal2world, pitch)`，返回最佳 yaw 与误差；`SolvePose` 之后调用，保存 `yaw_raw`。
- `target.cpp`：`Initialize` 与 `Update` 使用优化后的 `armor_yaw`。
- 普通装甲 `pitch = +15°`，前哨站 `−15°`（常量；当前目标只需 +15°）。

**算法**

```text
camera_forward_world = R_gimbal2world · R_camera2gimbal · (0,0,1)
yaw0 = limit_rad(atan2(forward.y, forward.x) − 70°)
for i in 0..139: yaw = yaw0 + i·1°
    e(i) = Σ|corner_obs − corner_reproj|
取 e 最小
```

**验收**

- 双板帧两块板法向差 ≈ 90°（日志实测 90.0°），允许 ±5°。
- 优化后的重投影误差 ≤ IPPE 原解。
- 斜视角（法向与视线夹角 > 45°）时 `proj_err_px < 8`。

**失败分叉**

- 最优落在区间端点 → 搜索中心（相机光轴）算错。
- 面序 180° 错 → `yaw_raw` 与优化值混淆。

### 阶段 4：像素四门关联

**做什么**

照 `tracker.cpp:398-558`，用预测面重投影四点与检测四点做四门 + 贪心配对，替换当前的法向角/位置门。

**落点**

- `tracker.cpp`（原 `multi_target.cpp`）：`QuadCost(predicted, measured)` 逐行照参考；代价矩阵 `候选 × 预测面`；贪心取全局最小；每个匹配项调用 `Target::Update(armor, face, ...)`。
- 删除 `MatchFace()` 与 `face_gate_rad`、`position_gate_m`。
- YAML/常量新增四门：

```yaml
center_gate_px: 100.0
corner_gate_px: 140.0
angle_gate_rad: 0.8
perimeter_ratio_gate: 0.6
```

**算法**

照 §3.5 的四项误差与代价；四项任一超门即无效，不做“后备宽门”。

**验收**

- 正常跟踪 60 s，有效配对率 > 95%。
- 双板帧两块板同时配对到不同面。
- 人造同号多检出/斜视角错误候选时被门拒，`r` 单帧变化 < 0.05 m。
- `cost` 与 `proj_err_px` 日志可解释每次匹配。

**失败分叉**

- 全部候选被拒 → 预测面重投影的姿态（阶段 1/3）或 `size`。
- 同一观测被用两次 → 贪心 `used_observation` 标记。
- 正常帧被拒 → 看 `corner_error` 分布，先不放大门限。

### 阶段 5：8 维图像角点观测

**做什么**

补 `update_image_points`，并让 `Update()` 先走它、失败回退 ypda；`apply_state_limits` 只在图像观测成功后执行（照参考）。

**落点**

- `ekf.hpp`：观测维数改为动态（`Eigen::Dynamic`），状态维 11 保持不变，4 维与 8 维共用实例。
- `target.cpp`：新增 `UpdateImagePoints(corners, face, ...)`，照 `target.cpp:352-414`。
- `Update()` 顺序固定为：`update_count_++` → 图像观测尝试 → 失败回退 ypda → 仅图像成功时 `apply_state_limits`。
- `Target::Diverged()` 改为参考的 `r ∈ (0,0.8) && r+l ∈ (0,0.8)`。
- YAML：`image_observation.enabled`、`image_point_sigma_px`（参考默认 8.0），与 `pnp_*` 分开。

**算法**

```text
z = 四角 x/y（8 维），h(x) 由状态反投
H 仅对 x, y, z, a, r, l, h 差分（1e-3 m / 1e-3 rad）
R = σ_px² · I8
```

**验收**

- 双板可见 10 s：`r` 在 `r_ref ± 0.03 m`，`P_rr` 下降或走平，`chord_res < 20 mm`。
- 8 维残差（四角平均）< 8 px；回退 ypda 的帧占比 < 10%。
- `r` 在 `(0, 0.8)` 内且不再贴 0.05/0.50；`diverged` 只在真正越界时触发。
- `image_point_sigma_px` 4→8 时 r 稳态不变、抖动变大。

**失败分叉**

- 发散 → 角点顺序（LT/RT/RB/LB）或灯条方向符号。
- 半径不收敛 → 单板帧不可观，属正常；看双板帧。
- 回退率高 → 投影非有限，查状态是否已越界。

### 阶段 6：NIS 与状态机判据

**做什么**

照 `tracker.cpp:209-216` 加“最近 100 次更新失败 ≥ 80 次 → lost”，并把 NIS 写进日志。

**落点**

- `ekf.hpp`：保留参考的 NIS 定义（**修正后**残差，`extended_kalman_filter.cpp:55-70`）与 `window_size = 100`。
- `target.hpp/.cpp`：暴露 `recent_nis_failures()` 计数与窗口大小。
- `tracker.cpp`：`track()` 在 `diverged` 之后加 NIS 判丢。
- `vision.yaml`：`nis_threshold`（参考 0.711，自由度 4、修正后残差）。

**为什么照参考用 0.711**：参考的 NIS 用 `z − h(x_修正后)` 计算（先更新 x/P，再算残差），与它 0.711 的标定配套。本工程 `ekf.hpp` 当前是修正前残差——这一步要把计算顺序改成参考的，否则阈值不可移植。

**验收**

- 正常跟踪 60 s：NIS 失败数远低于 80/100，不误判丢。
- 人为喂错面观测：失败数在窗口内累积到 80 后 `state=lost`，自瞄停发。
- 半径钳到边界的那次更新后：`diverged=1`，状态机回 lost（因为图像路径的钳制与 `(0,0.8)` 判据之间留有 0.05~0.50 的空隙不再被掩盖）。

**失败分叉**

- 正常帧全失败 → NIS 计算顺序/R 是否与参考一致。
- 永不判丢 → 窗口是否真的在滑、`window_size` 是否为 100。

## 6. 顺序理由

1. **阶段 0 先做**：参考的观测、关联、状态机都挂在 `Tracker + Target` 这个结构上；槽位层不拆，后面的代码无处落地。
2. **阶段 1 在 2 之前**：R 的传播函数以世界系 `(yaw, pitch, distance)` 为输出，坐标系不定，R 写出来要改两遍。
3. **阶段 3 在 4 之前**：四门用预测面重投影，重投影的法向角来自 `optimize_yaw`；法向有二义解时四门也会选错面。
4. **阶段 4 在 5 之前**：8 维观测依赖正确的面配对；先有像素四门，8 维才有意义。
5. **阶段 6 在 5 之后**：NIS 判的是更新残差，没有图像观测时残差统计的分布与参考不同。
6. **阶段 7 最后**：所有数值先照参考，再按本机数据核对；不提前调。

## 9. 不在本计划内

- **多跟踪器/多槽。** 等参考项目本身跑通、本工程确实需要同时跟多辆车时再做；本次删除 `MultiTargetTracker` 的槽位层。
- **目标类型切换的完整验证。** 结构上保留参考的 `is_balance/outpost/base` 分支与对应 `armor_num`，当前只验证 `Three + Small` 的四面分支。
- **实机 IMU 接入。** 参考用 `set_R_gimbal2world(quaternion)`；本工程用 TF 求得同一个矩阵，接口保持不变。实机时把 TF 换成下位机姿态即可。
- **检测器与 ROI。** 参考的 `dynamic_roi`、全向感知切换（`switching` 状态）不在本轮；本工程检测器已固定为 0526 TensorRT。
- **可视化。** 参考画检测板（青）+ 全部预测面（绿）+ 自瞄板（红）+ 状态文本；本工程对齐即可，不作为独立问题。
