## 2. 病灶

### 2.1 `ArmorTracker` 名不副实

它持有 11 维状态 `[cx, vx, cy, vy, cz, vz, a, w, r, l, h]`，推出整车的四个面，是车辆级状态估计器；参考里这个类叫 `Target`。现在的名字会被读成“单块装甲板的跟踪器”，与 `DetectedArmor`（单块检测结果）混淆。共 34 处引用、5 个文件。

同时 `TrackerConfig` 里嵌着 `ArmorTrackerConfig tracker`，使用处写成 `config_.tracker`、`tracker_config_.tracker`，变成“tracker 的 tracker”。

### 2.2 尺寸参数传进去又被丢掉

四处丢弃：

- `ArmorTracker::ObservePoints()`：`(void)dimensions`（`armor_tracker.cpp:124`）
- `ArmorTracker::ProjectFace()`：`(void)dimensions`（`armor_tracker.cpp:218`）
- `ReprojectArmor()`：内部固定 `MakeObjectPoints(size, ArmorDimensions {})`（`armor_pose.cpp:393`）
- `YpdaMeasurementCovariance()`：同样固定默认尺寸（`armor_pose.cpp:420`）

初始化与 PnP 路径用的是调用方传入的 `dimensions`，预测/关联用的是默认值。一旦 YAML 改了实际板宽，两条路径就会系统性地对不上。

量化：小装甲板默认宽 `W=0.135 m`，本机 `fx=1303.68`。距离 `d=2 m` 时投影像素宽

```text
w_px = W · fx / d = 0.135 × 1303.68 / 2 = 88.00 px
```

若实际宽度是 0.140 m，预测仍是 88.00 px、观测是 91.26 px，差 3.26 px（3.7%）。在 8 px 的观测噪声下是 0.41σ，不足以被四门拒绝，但会持续偏置关联与 NIS。

### 2.3 生命周期散在四处

`target_.Reset()` 共 5 个调用点：`SetTarget` 一次、`AdvanceState` 两次、NIS 分支、Diverged 分支。其中 NIS 与 Diverged 两个分支各自重复了一整套

```text
target_.Reset();
report_.active = false;
report_.converged = false;
report_.last_face = -1;
report_.state = Lost;
report_.detect_count = 0;
report_.temp_lost_count = 0;
```

共 12 行 × 2 份。状态机里再 Reset 一次，同一件事有四个入口。

### 2.4 `estimate_shape` 是死开关

9 处引用里没有一处把它置为 true：头文件默认 false、YAML 写 false、`UpdateImagePoints` 和 ypda 分支按它决定 H 是否包含 r/l/h、`Predict` 按它决定形状量过程噪声。注释写的是“多面观测稳定后才打开”，但没有任何代码在多面帧打开它。

结果：r/l/h 永远冻结在 `0.2/0/0`，不会收敛，也不会被拉坏。这是当前“能稳定跟单板、但整车半径永远是初值”的直接原因。

### 2.5 已经偏离参考的四处

| 位置 | 现在 | 参考 |
| --- | --- | --- |
| 匹配 | 全枚举一对一，`5^N` 个叶子（N=4 时 625） | 贪心，至多 `N·F·min(N,F)` 次比较（N=F=4 时 64） |
| 状态机 | `AdvanceState` 内 `Reset()` | 只改状态，重建留给下一帧 `set_target` |
| 发散 | 连续撞边界 ≥5 次也判发散 | 只看 `r`、`r+l` 是否在 `(0, 0.8)` |
| NIS | `UpdateCount() >= 10` 硬编码 | 无最小样本限制 |

前两项不影响正确性，但和“严格照参考”的约束冲突；后两项是新增的保护逻辑，需要明确保留还是删掉。

### 2.6 单板为什么收敛不了 r/l/h

单块板的观测是 8 个像素分量。状态里与这一块板有关的量是 `cx, cy, cz, a`，以及 `r`（面 0/2）或 `r+l`（面 1/3），再加 `h`（面 1/3）。

从 `ArmorCenter()` 的式子

```text
面心 = 圆心 − r · (cos a, sin a, 0)
```

可以得到一个严格的零空间方向：圆心沿 `(cos a, sin a, 0)` 平移 `ε`，同时 `r` 增加 `ε`，面心完全不变，八个像素观测也完全不变。所以单板观测的雅可比至少有一个零特征方向，`r` 与圆心的法向分量永远不可分。

面 1/3 更直接：`r` 和 `l` 在观测里只以 `r+l` 出现，两列雅可比完全相同，单板永远只能估出 `r+l`，估不出 `r` 和 `l` 各自。

这就是“单板连圆心都确认不了”的数学原因；也说明正确做法是单板时冻结 r/l/h，而不是指望它收敛。

用日志里的双板帧可以反算真值：观测板心 `(0.065,-0.058,2.009)` 与 `(0.341,-0.033,1.934)`，弦长

```text
chord = √(0.276² + 0.025² + 0.075²) = 0.287 m
```

对称四面车 `l=0` 时 `chord² = 2r²`，所以 `r = chord/√2 = 0.203 m`。同一时刻滤波器给的是 `r=0.291 m`，误差 0.088 m，占真值的 43%。

## 4. 分步骤

### 步骤 1：纯改名（零行为变化）

**做什么**：文件改名、类/结构体/成员改名，更新全部引用。

**落点**：
- `armor_tracker.hpp/cpp` → `target.hpp/cpp`；类 `ArmorTracker` → `Target`；`ArmorTrackerConfig` → `TargetConfig`。
- `TrackerConfig::tracker` → `target`；`Tracker` 内部成员 `target_` 类型改为 `Target`。
- `Tracker::Armors()` / `Target::Armors()` → `Faces()`；`Snapshot` 随类名。
- `ros2_layer/node/vision/vision_node.hpp` 的 include、类型与 `tracker_config_.target`。
- `framework/CMakeLists.txt` 的源文件登记。

**验收数字**：
- `rg -n "ArmorTracker|armor_tracker" framework project ros2_layer` = **0**。
- `rg -n "\.tracker\b" framework project ros2_layer` = **0**。
- `colcon build` 三个包，stderr 为空。
- 同一场景跑 60 s，`state / face / resets / updates` 的序列与改名前一致，`r` 的逐秒值差 ≤ 0.005 m（只允许仿真的随机差异）。

**失败分叉**：
- 编译报未定义符号 → 按报错逐个补，`rg` 应为 0 而非“看起来没有”。
- include 路径仍指向旧文件 → 检查 `install/` 里的旧头文件，重新 build 而不是直接改 install。

### 步骤 2：把 `dimensions` 接通（行为变化，仅在非默认尺寸时）

**做什么**：让预测、关联、PnP 三条路径使用同一份实物尺寸。

**落点**：
- `ReprojectArmor(..., const ArmorDimensions& dimensions, ...)`，内部 `MakeObjectPoints(size, dimensions)`。
- `YpdaMeasurementCovariance(..., const ArmorDimensions& dimensions, ...)` 同理。
- 删除 `ObservePoints()` 与 `ProjectFace()` 里的 `(void)dimensions`，一路透传。
- 调用点：`ArmorTracker`/`Target` 的观测、雅可比、残差回调。

**公式与量级**：投影宽 `w_px = W·fx/d`；默认值下与现状逐点相同。`W` 从 0.135 改到 0.140、`d=2 m` 时，

```text
88.00 px → 91.26 px，Δ = 3.26 px（3.7%）
```

**验收数字**：
- `rg -n "\(void\)dimensions|ArmorDimensions \{\}" framework` = **0**。
- 用默认 `ArmorDimensions{}` 时，四角投影像素与改动前逐点差 **< 1e-9 px**。
- 用 `W=0.140` 时，2 m 处的投影宽为 **91.26 ± 0.1 px**。

**失败分叉**：
- 默认尺寸下投影变了 → 说明有调用点仍在用别的尺寸，按 `rg MakeObjectPoints` 逐个对。
- 非默认尺寸下关联变差 → 先查初始化（`Initialize`）与观测是否用同一份 `dimensions`。

### 步骤 3：生命周期收口（行为变化）

**做什么**：所有“判丢重建”走一个函数。

**落点**：
- `Tracker` 增加 `void ResetTarget(ResetReason reason)`：`target_.Reset()`、清 `report_`、`++report_.resets`、写 `last_reset_reason`。
- NIS 分支与 Diverged 分支改为调用它；删除两份重复块。
- `AdvanceState()` 里的两处 `Reset()` 去掉，恢复参考“状态机只改状态”；下一帧 `SetTarget` 本来就会 `Reset()`。
- `Tracker::Active()` 改为同时要求 `report_.state != Lost`，消除“状态 lost 但 Active() 为真”。

**验收数字**：
- `rg -n "target_\.Reset" framework` = **2**（`SetTarget` 内一次、`ResetTarget` 内一次）。
- 一次重建事件 `resets` 只加 **1**；日志里 `resets` 的增量 = 该秒内 `reset=` 变化的次数。
- 目标离开视野后 `≤ max_temp_lost_count/fps ≈ 25/70 = 0.36 s` 内 `active=0`。

**失败分叉**：
- `resets` 一次加 2 → 有分支既调了 `ResetTarget` 又走了状态机 Reset。
- 重建后立刻又 lost → 检查 `last_reset_reason`，若是 `nis` 且失败率来自旧目标，检查 `reset_nis()` 是否在 `Reset()` 里（当前已有）。

### 步骤 4：让 `estimate_shape` 真正工作（行为变化）

**做什么**：按“本帧匹配到几个面”自动决定估不估 r/l/h，不再依赖一个永远为 false 的配置。

**落点**：
- `Tracker::UpdateTarget()`：枚举得到 `matches` 后，`const bool estimate_shape = matches.size() >= 2;`
- `Target::Update(..., bool estimate_shape)` 传入；`UpdateImagePoints`、ypda 的 H 只在 true 时包含 `kRadius/kRadiusGap/kHeightGap`；`Predict` 的形状过程噪声只在 true 时非零；`ApplyLimits` 只在 true 时执行。
- 删除 `TargetConfig::estimate_shape` 与 YAML/节点里的同名参数（或保留为“总开关”，默认 true；二选一，不能两者并存）。

**公式与依据**：
- 单板：雅可比至少有 1 维零空间，`r` 与圆心法向分量不可分；面 1/3 的 `r`、`l` 两列相同，只能估 `r+l`。
- 双板：相邻面弦长 `chord² = r² + (r+l)²`；对称车 `l=0` 时 `r = chord/√2`。实测帧 `chord=0.287 m → r=0.203 m`。
- 单次更新自由度：单板匹配时形状量不进 H（4 个状态量参与）；双板时 7 个状态量参与，两个面的弦长和相对转角提供额外约束。

**验收数字**：
- 单板连续 600 帧：`|Δr|`、`|Δl|`、`|Δh|` 每帧 **≤ 1e-9**（冻结）。
- 双板帧：`|r − chord/√2|` **≤ 0.02 m**。
- 同一 60 s 场景：`resets = 0`、`nis_rate < 0.2`、`r` 稳定在 **0.18~0.22 m**（三号车实测弦长反算 0.203 m）。
- `limit_clamps` 增量 **= 0**（不再贴边）。

**失败分叉**：
- 单板 r 仍在动 → H 里形状列没删干净，或 Q 仍在加噪声。
- 双板 r 不动 → `matches.size() < 2`；先查四门是否把第二块拒了，再查 label/size 过滤。
- 双板 r 跳变 → 两个面被配到 `{0,2}` 或 `{1,3}` 同组；先查面序，不要先调噪声。

### 步骤 5：关联算法定版（可选，需先决策）

**做什么**：保留全枚举或恢复参考的贪心，二选一，写进代码注释和本文。

**量级**：`N` 个候选、`F=4` 个面时，全枚举最多 `(F+1)^N` 个叶子（N=4 时 625），贪心至多 `N·F·min(N,F)` 次比较（N=F=4 时 64），约 **9.8×** 的差别。跟踪器频率约 70 Hz，两者都不构成性能问题。

**验收数字**：所选方案下步骤 4 的全部指标不变。

**失败分叉**：贪心版本在高代价候选上出现错误配对 → 保持全枚举；全枚举导致最坏帧耗时增加 > 0.2 ms → 改成按代价排序后的回溯或匈牙利。

## 5. 顺序为什么不能换

1. **改名必须在结构改动之前**：34 处引用靠编译器一次性找齐；先改结构再改名，diff 里会混着语义变化和符号变化，无法区分哪一步引入了行为差异。
2. **尺寸接通必须在形状估计之前**：步骤 4 打开 r/l/h 后，预测与观测必须使用同一份尺寸；否则 r 会被尺寸差系统性推偏。
3. **生命周期必须在形状估计之前**：多面帧打开估计后，重建入口若不唯一，`resets` 会被重复计数、NIS 历史与形状状态可能对不上。
4. **关联定版最后**：它只影响匹配选择，不影响尺寸与形状的数学前提；放在最后可以单独验收是否回归。

## 6. 失败回退表

| 症状 | 先查 | 再查 | 最后才查 |
| --- | --- | --- | --- |
| 改名后编译不过 | 旧符号残留（`rg`） | include 路径与 CMake 源文件登记 | install 里的旧头文件 |
| 默认尺寸下投影变了 | `MakeObjectPoints` 调用点 | `ArmorDimensions` 是否被局部构造 | 尺寸单位（mm/m） |
| 非默认尺寸下关联变差 | 初始化与观测是否同尺寸 | 四门门限是否随尺寸缩放 | 检测角点精度 |

| 双板 r 不收敛 | `matches.size()` | 四门拒绝原因 | 弦长公式与 `l` 的符号 |
| `cost` 高仍被接受 | 单项误差是否贴门 | 是否该加总代价门（参考没有） | 重投影姿态与尺寸 |

## 7. 本文不做的事

- 不调 `point_sigma_px`、P0、`accel_variance`、`angular_accel_variance`。
- 不改 `ReprojectArmor` 的轴约定、`FrameTransform` 的方向。
- 不改节点层的数据流、话题名与日志格式（除改名带到的类型名）。
- 不在本规划里新增总代价门、冻结逻辑以外的新机制；步骤 4 的自动开关是唯一的例外，且必须先按上面验收。
