## 1. 现在是什么状况

### 1.1 已经对地方

- 检测、PnP、四面模型、EKF（11 维）都已经和参考同构。
- 跟踪稳定时，`face` 预测和 `observed` 能对上（实测差值 < 0.03 m）：

  ```text
  face=0 xyz_cam=(0.146, 0.046, 1.852)
  observed xyz_cam=(0.146, 0.047, 1.871)
  ```

- 同号多检出不再抢槽（按预测距离选），敌方颜色在节点层过滤，四面绘制、装甲尺寸、自瞄指令都已接上。

### 1.2 没对的地方：没有状态机

现在 `MultiTargetTracker` 的生命周期只有两个状态，且都隐含在数据里：

```text
未初始化  --第一帧检测-->  已初始化  --连续 5 帧被门拒-->  未初始化（Reset）
```

也就是说：

| 事件 | 现在怎么做 | 后果 |
| --- | --- | --- |
| 首次看到车 | 一帧检测就直接建状态 | 单帧 PnP 二义解会直接变成初值 |
| 跟踪中偶发丢帧 | 只 `Predict`，`losses++` | 尚可 |
| 连续 5 帧被门拒 | `Reset()`，丢掉全部状态 | 状态反复重置，永远停在"刚起跑" |
| 目标消失 | 永远不会主动判丢 | 槽一直 `active=1`，自瞄继续发旧状态 |

### 1.3 日志上的直接证据

同一次运行里：

```text
updates: 321 → 20 → 96 → 2 → 76 → 22 → ...    多次归零
gate:    386 → 403 → 427 → ... → 608           持续增长
r:       0.207 → 0.350 → 0.050 → 0.400 → 0.500 → 0.050 → ...
```

- `updates` 归零 = `Reset()` 被触发；
- `r` 在物理边界 0.05 / 0.50 之间来回撞 = 状态刚建立就发散；
- `losses` 长时间不变 = 每帧都有检测进槽，不是漏检；
- `observed` 里常驻一条 `(-1.401, -0.104, 2.805)` 几乎不动，疑似误检或静止目标。

结论：不是"某一帧解错"，而是**建状态的门槛太低、丢状态的时机太早**。

## 2. 参考项目怎么做

### 2.1 四状态机（`tracker.cpp:302-360`）

```text
lost ──found──> detecting ──连续 min_detect_count 帧──> tracking
                    │                                      │
                    └──一帧没找到──> lost                    └──一帧没找到──> temp_lost
                                                                    │
                                                       连续 max_temp_lost_count 帧
                                                                    │
                                                                    v
                                                                  lost
```

关键点：

- **`lost` 状态下每帧都调用 `set_target` 重新初始化**，而不是"只初始化一次然后死守"。
- **进入 `detecting` 后要连续确认**：`min_detect_count: 5`，即连续 5 帧都找到才转 `tracking`。单帧误检进不了跟踪。
- **`tracking` 丢一帧只转 `temp_lost`**，不立刻重置；`temp_lost` 期间继续用 EKF 预测。
- **`temp_lost` 连续 25 帧（前哨站 75 帧）没找到才回 `lost`**，才允许重新初始化。
- **`diverged()` 直接判 `lost`**：半径跑出范围就整条扔掉。

### 2.2 关联门（`tracker.cpp:440-480`）

参考的四个门同时满足才更新：

| 门 | 配置值 | 含义 |
| --- | --- | --- |
| `center_gate_px` | 100 | 预测中心与观测中心像素距离 |
| `corner_gate_px` | 140 | 四角点平均像素误差 |
| `angle_gate_rad` | 0.8 | 四边方向角误差 |
| `perimeter_ratio_gate` | 0.6 | 预测周长与观测周长之比 |

我们是"角度门 + 位置门"两道，且位置门是米制、阈值 1.5 m。

### 2.3 优先级与选目标（`tracker.cpp:253-262`）

```cpp
armors.sort(离图像中心由近到远);
armors.sort(按兵种优先级);
```

两次排序后取首位作为本帧目标；跟踪中若出现更高优先级目标则切换。
我们只有一槽一号，用"预测距离"代替优先级。

### 2.4 发散判据（`target.cpp:470-471`）

```cpp
r  ∈ (0, 0.8)
r+l∈ (0, 0.8)
```

超出即 `diverged()` → `lost`。我们的 `Diverged()` 用 `[0.05, 0.50]` 并配合 `Reset()`。

## 3. 差距汇总

| 项 | 参考 | 现在 | 影响 |
| --- | --- | --- | --- |
| 状态机 | lost/detecting/tracking/temp_lost | 无，只有 initialized | 反复重置、永远不判丢 |
| 建状态门槛 | 连续 5 帧 | 1 帧 | 单帧误检直接成为初值 |
| 丢帧容忍 | 25 帧 | 5 帧门拒即重置 | 偶发斜视角就全丢 |
| 关联门 | 4 门（像素+角度+周长） | 2 门（角度+米制位置） | 远处/斜视角的关联偏松或偏紧 |
| 对外输出 | 仅 tracking 时给目标 | 只要 converged 就给 | 重置前后状态跳变也会驱动自瞄 |
| 发散处理 | 判 lost 后重新 set_target | Reset 后下一帧就重建 | 结构相同，缺"连续确认" |

## 4. 建议的改法（按参考对齐）

在 `MultiTargetTracker` 里加回状态机，`ArmorTracker` 不动：

1. 每槽加 `TrackerState { Lost, Detecting, Tracking, TempLost }` 与 `detect_count`、`lost_count`。
2. `Update` 里按编号分派后，逐槽：
   - `Lost`：`found` → `Initialize`（当帧），`detecting_count=1`，状态 → `Detecting`；不对外报告收敛。
   - `Detecting`：连续 `found` 累加，达到 `min_detect_count` → `Tracking`；任一帧 `!found` → 回 `Lost` 并 `Reset()`。
   - `Tracking`：`!found` → `TempLost`；`found` 正常更新。
   - `TempLost`：`found` → `Tracking`；连续 `max_temp_lost_count` 帧 `!found` → `Lost` + `Reset()`。
3. 新增参数（进 `MultiTargetConfig`，YAML 可调）：
   - `min_detect_count`（默认 5）
   - `max_temp_lost_count`（默认 25）
   - `diverged` 判据沿用 `ArmorTracker::Diverged()`
4. `Converged(slot)` 改为“状态机为 `Tracking` 且 `ArmorTracker::Converged()`”，自瞄和绘制只看这个。
5. 现有 `reset_after_rejects` 保留作为**兜底**（门拒超过 N 帧仍强制 `Lost`），但不再承担主要生命周期。

验收标准：

- 连续运行 60 s，`updates` 单调增长不归零；
- `gate` 增长后走平；
- `r` 收敛到 0.15~0.25 且不贴边界；
- 目标离开视野后 ≤ 1 s 内 `converged` 变 0，`/rm_gimbal/cmd` 发 `distance=-1`。
