# 云台静止时的跟踪效果（2026-10-22）

本文只用一组数据：**不按自瞄键、云台不动、目标车自转**，从锁定后连续跑 18 秒。
所有数字取自同一次运行的 `track` / `ekf` / `timing` 日志行，没有跨运行拼接。

对照场景（按住自瞄键、云台跟随转动）放在最后一节，用来回答"为什么静止就好"。

---

## 一、结论

云台静止时，整条链路（检测 → PnP → EKF → 四面外推 → 选面）是自洽的：

- 车心在 18 秒内的散布是 **x ±14 mm、y ±7.6 mm**
- 半径 `r` 稳定在 **0.2133 m ± 0.0042 m**（0.4%）
- 转速 `ω` 收敛到 **7.37 rad/s**，与真值 7.42 差 **0.7%**
- 换面周期 **0.212 s**，与 `90° / 7.42 rad/s = 0.2117 s` 差 **0.2%**
- 关联一次都没被门拒（`gate = 0`），全程只丢 1 帧

所以"跟踪不好"不是算法问题，是**相机位姿的时刻对不齐**，而这只在云台转动时才产生误差。

## 二、实测数据

### 2.1 生命周期

```

updates    = 1664 → 3491（17 秒内 +1827，约 107 次/秒）
losses     = 1（全程未增加）
gate       = 0
resets     = 3（都在开跑前的建目标阶段，reset=diverged）
```

`updates` 每秒 107 次而帧率只有 84 fps，因为双板帧一帧做两次更新。

| y | 2.5084 m | 2.495 ~ 2.521（26 mm） | **7.6 mm** |

18 秒内车心没有系统性漂移，只是小幅抖动。

### 2.3 车心 1 秒漂移（`drift1s`）

| | 值 |
| --- | ---: |

### 2.4 半径与转速

| 量 | 均值 | 范围 | 标准差 |
| --- | ---: | ---: | ---: |
| `r` | **0.2133 m** | 0.2032 ~ 0.2199（17 mm） | **4.2 mm** |

`l`（第二半径差）与 `h`（高度差）都接近 0，符合"四面等距等高安装"的物理事实。

### 2.5 观测残差与 NIS

| 量 | 实测 | 理论期望 |
| --- | ---: | ---: |
| `resid`（残差 RMS） | **1.14 px**（0.67 ~ 2.30） | 应接近 `point_sigma_px = 4.0` |
| `nis` | **0.60**（0.20 ~ 1.92） | 8 维观测下 `E[NIS] = 8` |
| `nis_rate` | **0.00 ~ 0.02** | ≤ 0.10 |

`nis_rate` 达标，但 `NIS` 均值只有期望的 1/13。这说明滤波器认为观测比实际更噪
（`resid / point_sigma = 0.285`，平方后乘 8 正好是 0.65，与实测 0.60 一致）。
**这不是错误，是观测权重偏低**——滤波器偏平滑。要更贴观测可以把 `point_sigma_px` 再降，
但当前参数下 `nis_rate` 稳定，暂不动。

### 2.6 状态协方差（`P diag`）

| 分量 | 范围 |
| --- | ---: |
| `cx` | 0.0029 ~ 0.0047 |
| `cy` | 0.0003 ~ 0.0006 |
| `cz` | ≈ 0.0000 |
| `angle` | 0.0009 ~ 0.0091 |
| `ω` | 0.133 ~ 0.861 |

`cy` 比 `cx` 小一个量级，因为相机主要沿 y 方向分辨横向位置。`cz` 几乎为 0，
说明深度由 PnP 直接给出、滤波器几乎不需要修。

### 2.7 换面周期

`face switch` 时间戳（截取前 8 次）：

```
3→2  501.79    2→1  501.99    1→0  502.19    0→3  502.44
3→2  502.63    2→1  502.84    1→0  503.05    0→3  503.27

理论值：`90° / 7.42 rad/s = 0.2117 s`。**差 0.2%。**

这条数据同时证明两件事：

1. 面序每 0.21 s 换一次是**物理换板**，不是关联错标
2. EKF 估出的 `ω` 与实际转速一致

```

**这些延迟在静止场景下是"坏数据"的来源，但不产生误差**，见下一节。

## 三、为什么云台静止效果就好

### 3.1 误差产生的唯一路径

观测进 EKF 之前要走三步：

```
图像时间戳 T
  → 从 PoseBuffer 插值出 map←相机 的位姿
  → 把 PnP 的相机系坐标换到 map 系
  → 送进 EKF
```

第 2 步用的是时刻 T 的位姿。如果这个位姿不是时刻 T 的（而是 T − Δ 的），
那么 map 系的观测点就整体错位：

```
位置误差 ≈ 距离 × sin(云台角速度 × Δ)
```

**误差正比于云台角速度。** 云台不动时角速度为 0，Δ 多大都不产生误差。

### 3.2 Δ 有多大

`pose offset` 是"图像时间戳 − 最新姿态样本时刻"，实测：

- 均值 32 ms，最大 122 ms
- `pose_hold_s = 0.08`：超过 80 ms 的帧直接丢弃（就是 `pose_missing` 那 16%）

所以实际用上的位姿，最多比图像晚 **80 ms**。

### 3.3 静止 vs 转动

以 4 m 距离、转速 7.42 rad/s 计算：

| 场景 | Δ | 云台转过 | 4 m 处横向误差 |
| --- | ---: | ---: | ---: |
| 静止 | 80 ms | **0°** | **0 m** |
| 转动 | 32 ms（均值） | 13.6° | 0.94 m |
| 转动 | 80 ms（上限） | 34.0° | 2.24 m |

对照实测：转动场景的 `vel` 冲到 7.21 / 8.00 m/s，车心位置在秒级跳到米级，
`r` 撞到 0.05 / 0.50 的钳制边界。量级对得上。

### 3.4 一句话

**云台静止时，"姿态时刻对不齐"这个缺陷被乘以 0；云台一动，它被乘以 7.42 rad/s。**

静止场景好，不是因为算法变好了，是因为唯一那个未修的问题不产生误差。

## 四、对照：同一套代码，云台转动

| 指标 | 云台静止 | 云台转动 |
| --- | ---: | ---: |
| `drift1s` 均值 | 0.031 m | 0.187 ~ 6.258 m |
| `vel` | 多数 < 0.13 m/s | 7.21 / 8.00 m/s |
| `r` | 0.2133 ± 0.0042 m | 0.050 / 0.118 / 0.150 / 0.291 / 0.500 m |
| `resid` | 1.14 px | 15 ~ 48 px |
| `nis_rate` | 0.00 ~ 0.02 | 0.24 ~ 0.70 |
| `resets` | 3（开局） | 2 ~ 3（`reset=nis`，运行中） |
| `pose_missing` | 7 ~ 17 | 11 ~ 18 |
| `tf_delay` | 65 ~ 92 ms | 62 ~ 101 ms |

**时间链路两个场景几乎完全一样。** 唯一变的是云台是否转动。

这条对照是"根因在姿态时刻、不在 TF 传输"的直接证据。

## 五、这组数据能证明什么、不能证明什么

**能证明：**

- 检测 → PnP → EKF 的几何链路是对的（`reproj ≈ 0.1 px`，`r` 波动 4 mm）
- 四面模型与实物一致（`l ≈ 0`、`h ≈ −0.013` 稳定）
- 面序关联正确（换面周期与转速吻合到 0.2%）
- EKF 参数（P0、`point_sigma_px`、`Q`）在静止场景下是自洽的

**不能证明：**

- 云台转动时的跟踪效果（那正是当前失败的部分）
- 选面逻辑（P6 刚写完，还没实跑）
- 提前量与弹道（P7 未开始）
- 实车效果（仿真无畸变、无噪声、真值理想）

**要注意：**

- 这组数据是**唯一的干净基线**。任何改动后应该先跑这个场景，确认没退化，再看转动场景。
- `NIS` 均值 0.60 远低于期望 8，说明观测权重仍偏低。当前不影响 `nis_rate`，
  但如果后续要提响应速度，这是第一个该调的地方。
