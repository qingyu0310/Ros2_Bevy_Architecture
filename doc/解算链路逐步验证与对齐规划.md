# 解算链路逐步验证与对齐规划

日期：2026-10-21
对象：`framework/algorithm/vision/pose/`、`framework/algorithm/vision/track/`、`framework/algorithm/vision/aim/`、`ros2_layer/node/vision/`
参考：`temp/Dust_infantry_vision-main`（`tasks/auto_aim/solver.cpp`、`target.cpp`、`tracker.cpp`、`planner/planner.cpp`）
前提：检测已确认可用（`det stats` 的 `rej color/label/geom` 全 0，`max_obj` 0.95），本规划不动检测器。

本文把"从一帧检测到云台角度"拆成 8 段，每段给一条可单独跑、可单独判定的测量。
执行时**按 P0→P7 顺序做，每段做完拿到验收数字再进下一段**。

## 0. 边界

1. **不动检测**：不改 `detect/`、不改 `model_decode.cpp`、不改 `score/confidence/nms` 三个门限。
2. **不调关联门限**：`center_gate_px`、`corner_gate_px`、`angle_gate_rad`、`perimeter_ratio_gate` 在 P5 判定之前保持现值（100 / 140 / 1.5 / 0.6），不得用放门限掩盖状态漂移。
3. **不新增话题**：地面真值全部取仿真已在 `/tf` 上发布的帧——
   `map → armor_N`（每块装甲板板心的世界位姿）、`map → odom → gimbal_link → camera_link → camera_optical_frame`、`gimbal_link → muzzle → muzzle_link`。
   `armor_N` 由 `third_party/bevy_robomaster_simulator-master/src/ros2/plugin.rs:224-228` 发布，是全局位姿，可以直接当 PnP 真值。
4. **一次只改一个变量**：同一段内改两处，效果归属说不清，退回重做。
5. **每段先测后改**：先在当前代码上把基线数字打出来，再改；改完用同一条测量复验。

## 2. 病灶

### 2.1 初始化协方差与真实转速差 14.8σ

`vehicle_ekf.cpp:524` 的 P0 对角（顺序 cx vx cy vy cz vz a w r l h）：

```text
0.01, 0.01, 0.01, 0.01, 0.01, 0.01, 0.09, 0.25, 0.04, 0.01, 0.01
```

参考 `tracker.cpp:390` 的 P0_dig（普通车）：

```text
1, 64, 1, 64, 1, 64, 0.4, 100, 1, 1, 1
```

对照：

| 状态 | 本工程 σ | 参考 σ | 真值 | 本工程是几 σ |
| --- | ---: | ---: | ---: | ---: |
| ω | 0.50 rad/s | 10.0 rad/s | **7.42 rad/s** | **14.8σ** |
| vx/vy | 0.10 m/s | 8.0 m/s | 可达 1.5 m/s | 15σ |
| a | 0.30 rad (17°) | 0.63 rad (36°) | 任意 | — |
| r | 0.20 m | 1.0 m | ~0.2 m | — |

**这条怎么算的**：`sqrt(0.25) = 0.5`，`7.42 / 0.5 = 14.84`。
滤波器在锁定瞬间认为 ω 只有 0.5 rad/s 的不确定度，而真实值是 7.42 rad/s——
它必须靠后续观测把 ω 从 0 拉到 7.42，每帧能提供的角度信息又只有
`ω·Δt = 7.42 × 0.012 = 0.089 rad`，收敛要几十帧，期间这段运动只能被解释成车心平移。
日志里 `vel = 3.72 m/s`、车心 1 s 漂 1.9 m，正是这个"用平移解释旋转"的产物。
参考把 P0 的 ω 放到 σ=10 rad/s，一次就把 7.42 包进去了，不存在这段过渡。

### 2.2 姿态滞后 30 ms 在小陀螺下等于 12.7° 的角度误差

允许窗口 `pose_hold_s = 30 ms`（`vision.yaml:32`），实测偏移最大 61 ms。
按底盘真值转速 7.42 rad/s：

```text
角度误差 = 7.42 × 0.030 = 0.223 rad = 12.7°
```

云台正在跟踪目标，相机姿态每滞后 30 ms，整条 `map ← 相机` 就转过 12.7°。
目标在 3.5 m 处被搬动 `3.5 × tan(0.223) ≈ 0.79 m`；按 61 ms 算是 `3.5 × tan(0.453) ≈ 1.69 m`。
**这和日志里车心 1.9 m 的跳变、`target_map` 1 s 内 2 m 的跳变是同一量级。**

### 2.3 单板帧无条件改写瞄准面

`tracker.cpp:153-161`：本帧一对都没配上就直接返回；配上时 `SelectAimMatch`
在**本帧的匹配列表**里选。单板帧只有一个匹配，`aim_switch_cost`（`vision.yaml:103`，5.0）
根本没有第二个候选可比，`last_face` 被无条件改写。

单板帧占绝大多数（`faces=1`），所以面序实际由"这一帧检测到哪块板"决定，
而不是由"哪块板该打"决定。日志 5.05 次/秒的切换率就是这么来的。

### 2.4 换面一次，四面整体转 90°，黄框位移 105 px

`vehicle_ekf.cpp:309-313`：`FaceAngle = angle + face · 2π/4`，`ArmorCenter` 用同一个角度算位置。
`last_face` 变一次，`angle` 与四面位置整体跳 90°，跳变幅度：

```text
弦长 = 2 r sin(45°) = 2 × 0.2 × 0.707 = 0.283 m
像素 = 0.283 × 1303.675 / 3.5 = 105 px
```

这是"黄框飞出去"的直接尺度。它是**结果**，不是原因；原因在 2.2 和 2.3。

### 2.5 观测模型与数据不自洽：NIS 均值超过 95% 分位

8 维像素观测的卡方 95% 分位是 15.507（`ekf.hpp:218`）。日志里单次 NIS = 16.21，
滑窗失败率 0.32。NIS 的期望值应当等于观测维数（8），实测明显偏大，
说明**残差与协方差假设不匹配**——要么实际角点噪声大于 `point_sigma_px = 8`，
要么状态已经偏到"预测与观测对不上"。P3 要把这两者分开。

### 2.6 观测噪声 8 px 从未与实测残差核对

`point_sigma_px = 8.0`（`vision.yaml:57`）与参考一致，但参考是 1808 px 焦距、另一台相机。
本机 fx=1303.675，同一块板在同样距离上的像素尺寸小 28%。
噪声应按残差实测重定，不能靠"和参考一样"。

### 2.7 瞄准面只能取本帧匹配面

参考的 `Planner::choose_aim_point`（`planner.cpp:71-141`）在**四个预测面**里选，
包含本帧没有观测、只靠状态外推的面，并且有 `lock_id` 与 coming/leaving 判据。
本工程的 `SelectAimMatch`（`tracker.cpp:198`）只在**本帧匹配到的面**里选。
单板帧因此无法保持上一帧的瞄准面，与 2.3 是同一条问题的两端。

## 3. 方法学约束

1. **真值唯一来源是 `/tf`**：`map → armor_N` 给板心世界位置与姿态；`map → camera_optical_frame` 给相机位姿真值；`gimbal_link → muzzle_link` 给枪口方向。
   不引入仿真侧新话题、不读仿真内部状态。
2. **每个判据都落成日志行**，格式固定、可直接 `grep`，不靠肉眼读图。
3. **同一段里只改一个量**；参数改动写进 `vision.yaml` 并在回话里列出旧值→新值。
4. **先量后改**：每段第一步是"在当前代码上打出这个数"，第二步才是改。
5. **不达标不许进下一段**：本段失败就走失败分叉，不带着偏差往上叠。
6. 全部测量在**同一场景**下做：仿真单目标、敌方蓝车、底盘按 `Q` 起小陀螺、距离 3~4 m、按住右键。

**落点**：

**验收数字**：

### P1 PnP 解算验证（`SolvePose`）

**做什么**：用真值量 PnP 的横向误差、深度误差、重投影误差、法向 yaw 误差。

**落点**：
- 被测函数 `framework/algorithm/vision/pose/armor_pose.cpp:318` `SolvePose`
- 修正候选：`armor_pose.cpp:516` `OptimizeYaw`（法向搜索）
- 日志加在 `vision_node.cpp` 的 `log_window`：每块配对成功的板打
  `pnp err lat=..m depth=..m reproj=..px yaw=..deg`

**算法与判据**：
- 横向误差 `e_lat = |(p_pnp − p_true) − ((p_pnp − p_true)·û)û|`，`û` 为相机视线单位向量
- 深度误差 `e_depth = |(p_pnp − p_true)·û|`
- 理论 1σ（角点噪声 σ_uv、板宽 W、距离 z）：

```text
σ_lat   = z · σ_uv / f
σ_depth = z² · σ_uv / (f · W)
```

  本机 f=1303.675、W=0.135 m、z=3.5 m：

| σ_uv | σ_lat | σ_depth |
| ---: | ---: | ---: |
| 8 px | 21.5 mm | **0.557 m** |
| 4 px | 10.7 mm | 0.278 m |
| 2 px | 5.4 mm | 0.139 m |

  也就是说：**深度方向单帧本来就不可信**（8 px 假设下 1σ 半米），
  EKF 的时间平滑是必需的；PnP 的验收要按横向 + 重投影为主。

**验收数字**：
- 重投影误差：均值 ≤ 2 px，95 分位 ≤ 4 px
- 横向误差：均值 ≤ 30 mm（对应 σ_uv ≈ 5 px 量级）
- 深度误差：均值 ≤ 0.20 m（对应 σ_uv ≈ 3 px）；P0 实测 `dist_avg` 0.18~0.20 m
  就是这个量，拆开横向/深度后这里才能定性
- 法向 yaw 误差：均值 ≤ 5°；相邻帧跳变 > 60° 的比例 ≤ 1%

**失败分叉**：

| 现象 | 先查 |
| --- | --- |
| 重投影 ≤ 2 px 但横向误差大 | 内参（`/vision/camera_info`）或板尺寸（`armor_pose.hpp:34-36`） |
| 重投影大且四角顺序相关 | 检测角点顺序，`armor_detector.cpp:523-528` 的 LT/RT/RB/LB 与 `MakeObjectPoints` 的物点顺序 |
| yaw 相邻帧跳 ~180° | IPPE 二义，`OptimizeYaw` 的搜索中心（`armor_pose.cpp:521-524`）用相机光轴而不是上一帧 yaw |
| yaw 系统性偏 | 板面倾角 `armor_pitch_rad`（15°）与仿真实际倾角不符 |

### P2 帧变换与时间同步

**做什么**：验证我们拼出来的 `map ← camera_optical_frame` 与 TF 真值一致，并量清图像时间戳与所用位姿时刻的差。

**落点**：
- `ros2_layer/node/vision/vision_node.cpp:364` `on_tf`（逐级拼链）
- `ros2_layer/node/vision/pose_buffer.hpp` `At()`（插值与 hold）
- `ros2_layer/node/vision/vision_node.cpp:243-254`（取姿态、累计 offset）

**算法与判据**：
- 一致性：同一时刻用 TF 直接查 `map ← camera_optical_frame`，与我们拼出来的比
  `|Δt| ≤ 5 mm`、`|ΔR| ≤ 0.2°`
- 时序：`offset = image_stamp − pose_stamp`，统计分布
- 姿态滞后换算成角度误差上界：`Δθ = ω_chassis · offset`，本机 `ω_chassis = 7.42 rad/s`

| offset | Δθ | 3.5 m 处位置误差 |
| ---: | ---: | ---: |
| 5 ms | 2.1° | 0.13 m |
| 10 ms | 4.2° | 0.26 m |
| 30 ms | 12.7° | 0.79 m |
| 61 ms（实测最大） | 25.9° | 1.69 m |

**验收数字**：
- 拼链与 TF 查询差 ≤ 5 mm / 0.2°
- `offset` 95 分位 ≤ 10 ms，最大 ≤ 20 ms
- 超窗丢帧率 ≤ 2%（当前 `pose_missing` 每秒 8~14 帧，占比 10~17%，不达标）

**失败分叉**：
- 拼链差大 → 检查父子方向：`/tf` 每条是 `header.frame_id → child_frame_id`，从相机往上走要用 `p_parent = R·p_child + t`
- offset 大但 TF 频率够 → 图像时间戳不是采集时刻，查 `camera_node` 的 header 转发
- offset 大且 TF 频率不够 → 提高 TF 发布频率，**不要**靠放大 `pose_hold_s` 顶（顶的是旧姿态，2.2 里 30 ms 已经是 12.7°）

### P3 观测模型自洽（NIS 与残差）

**做什么**：在状态不动的前提下，量"一帧观测的残差"和"滤波器假设的噪声"是否匹配。
这一步不修任何东西，只出数字。

**落点**：
- `framework/algorithm/vision/track/vehicle_ekf.cpp:369` `UpdateImagePoints`
- 在 `correct()` 前后取 `filter_.last_nis()`，并额外算 `residual_rms = sqrt(yᵀy / dim)`
- 日志加 `ekf resid rms=..px nis=.. dim=8`，每秒统计均值与 95 分位

**算法与判据**：
- 理论：若模型自洽，`E[NIS] = dim`（8 维时 ≈ 8），`nis_rate ≈ 0.05`
- 实际角点噪声估计：`σ_uv,actual = residual_rms / sqrt(2)`（残差含状态误差与观测噪声两部分，这里只作量级参考）

**验收数字**：
- `NIS` 均值 ∈ [4, 12]（8 维）
- `nis_rate` ≤ 0.10（当前 0.32）
- `residual_rms` 与 `point_sigma_px` 的比值 ∈ [0.5, 2.0]

**失败分叉**：

| 现象 | 判断 |
| --- | --- |
| NIS 大、残差 RMS 也大 | 状态偏了，回到 P4/P5；不要先动噪声 |
| NIS 大、残差 RMS 正常 | 协方差假设偏小（P 或 R 过紧），按残差重定 `point_sigma_px` |
| NIS 小、残差 RMS 大 | R 给得过大，观测被浪费 |
| 单板帧 NIS 明显大于多板帧 | 单板观测本身不可观，见 P4 |

### P4 初始化与过程噪声对齐参考

**做什么**：把 P0 与 Q 按参考对齐，再量"锁定后多久收敛到真值"。

**落点**：
- `framework/algorithm/vision/track/vehicle_ekf.cpp:524`（P0 对角）
- `framework/algorithm/vision/track/vehicle_ekf.cpp:272-289`（Q）
- `framework/algorithm/vision/track/vehicle_ekf.hpp:44-58`（配置项）

**算法与公式**：

P0 改为参考的普通车取值（`tracker.cpp:390`）：

```text
P0 = diag(1, 64, 1, 64, 1, 64, 0.4, 100, 1, 1, 1)
```

对应 σ：位置 1 m、速度 8 m/s、角度 36°、角速度 10 rad/s、半径 1 m。
这样 `ω_true = 7.42` 落在 `0.74σ` 内，第一帧就不需要"从 0 爬上去"。

Q 的形状量：参考对四面车**始终**给 `v3 · Δt²`（`target.cpp` 的 `Q(8,8)=v3*c`，v3=0.1），
本工程在单板帧给 0（`vehicle_ekf.cpp:286`）。单板帧不给噪声会让 `P_r` 塌到 8e-5，
之后即使出现多板帧，r 也几乎不动。

**验收数字**（锁定后逐帧记录，与 `/tf` 真值比）：
- ω 进入 `7.42 ± 1 rad/s` 所需帧数 ≤ 10（0.12 s）
- r 稳定在真值 ± 0.03 m，且 `limit_clamps = 0`
- 车心速度稳态 ≤ 0.3 m/s（当前 3.72 m/s）
- 车心位置 1 s 内漂移 ≤ 0.10 m（当前 1.9 m）

**失败分叉**：
- ω 收敛快但 r 发散 → 形状量过程噪声过大，回到 0.1 量级单独调
- ω 收敛了但车心仍漂 → 不是 P0 问题，转 P2（姿态滞后）
- NIS 恶化 → P0 放宽后观测权重相对变大，回 P3 复核残差

### P5 关联与面序稳定性

**做什么**：让单板帧不再改写面序。照参考的做法——关联给的是 `matched_id`，
面序的连续性由"同一块物理板"保证，而不是由"本帧哪块板代价最小"保证。

**落点**：
- `framework/algorithm/vision/track/association.cpp:120` `Associate`
- `framework/algorithm/vision/track/tracker.cpp:139` `UpdateVehicle`
- `framework/algorithm/vision/track/tracker.hpp` 的 `TrackerReport`（加 `face_switches` 计数）

**算法与判据**：
- 参考 `Target::update`（`target.cpp:164-249`）在 id 变化时只记 `is_switch_`，不阻止；
  真正阻止换面的是 P6 的瞄准面选择。所以本段只做**测量 + 单板帧保护**：
- 单板帧（`matches.size() == 1`）时，若该匹配的 `face != last_face`，要求代价比
  当前面预测的代价低出一个门限才允许改写，否则保持 `last_face` 不变、状态照常修正。
  判据写成：`cost_new < cost_current_predicted · 0.7`
- 换面计数：`face_switches` 每秒输出一次

**验收数字**：
- 面序切换 ≤ 1 次/秒（当前 5.05 次/秒）
- 每次切换时，同一块检测板与切换前后两个预测面的像素中心距离比 ≥ 1.5
  （即确实换到了另一块物理板，而不是同一块板换了标号）
- 切换后 3 帧内 NIS 不出现连续超限

**失败分叉**：
- 切换率降了但丢帧率上升 → 门限过严，把 0.7 调到 0.85
- 切换率不降 → 说明不是单板帧在切，回 P3 查是否多板帧代价算错
- 换了物理板也不切 → 门限过松，回到 0.7 并检查 `perimeter_ratio_gate`

### P6 瞄准面选择（照参考 `choose_aim_point`）

**做什么**：把瞄准面从"本帧匹配面"改成"四个预测面里按可射击性选"，并加 `lock_id`
与 coming/leaving 判据。这是参考 `planner.cpp:71-141` 的做法，也是 2.7 的修法。

**落点**：
- 新增 `framework/algorithm/vision/aim/aim_selector.{hpp,cpp}`（纯函数，不引 ROS）
- 替换 `framework/algorithm/vision/track/tracker.cpp:198` `SelectAimMatch`
- 调用点 `ros2_layer/node/vision/aim_publisher.cpp:147`（`last_face` → 选择结果）
- 参数进 `project/params/vision.yaml` 的"瞄准面"分组

**算法与公式**（照参考）：

```text
center_yaw = atan2(cx, cy)                     # 车心的球坐标 yaw
Δa_i       = limit_rad(face_yaw_i − center_yaw)

未跳变过（jumped == false）：直接取 0 号面
|ω| ≤ 2 rad/s（非前哨站）：
    可射集合 = { i : |Δa_i| ≤ 60° }
    |集合| > 1：lock_id 若在集合内保持，否则取 |Δa_i| 最小者
    |集合| = 1：退出 lock，取该面
|ω| > 2 rad/s（小陀螺）：
    |Δa_i| > coming_angle(55°)            → 跳过
    ω > 0 且 Δa_i < leaving_angle(20°)     → 选 i
    ω < 0 且 Δa_i > −leaving_angle(20°)    → 选 i
```

**验收数字**：
- 瞄准面切换 ≤ 1 次/秒（当前 5.05 次/秒）
- 单板帧下瞄准面保持率 ≥ 80%（即单板帧里不换面的比例）
- 瞄准点 `target_map` 相邻帧位移 ≤ 0.15 m（3.5 m 处折合 2.5°）

**失败分叉**：
- 面选对了但目标始终在画面边缘 → coming/leaving 角度按仿真实际转速重定（先量再调）
- 频繁在两个面之间跳 → `lock_id` 未生效，检查 `jumped` 标志的置位条件
- 选到背面 → `Δa_i` 的基准 `center_yaw` 用了车心球坐标，注意 `x/z` 顺序（状态是 `x vx y vy z vz`，车心水平面是 x-y）

### P7 弹道与提前量

**做什么**：把"当前面中心 → 角度"改成参考的"预测到弹丸到达时刻 → 抛物线仰角"。

**落点**：
- 新增 `framework/algorithm/vision/aim/trajectory.{hpp,cpp}`（照 `temp/Dust_infantry_vision-main/tools/trajectory.cpp`）
- `framework/algorithm/vision/aim/aim_solver.cpp:25` `SolveAim` 增加 `bullet_speed` 与 `fly_time` 迭代
- `ros2_layer/node/vision/aim_publisher.cpp:97-104` 传入初速

**算法与公式**（照参考 `trajectory.cpp`）：

```text
g = 9.7833 m/s²
a = g d² / (2 v₀²),  b = −d,  c = a + h
Δ = b² − 4ac
tanθ = (−b ± √Δ) / (2a)，取飞行时间较短的那个根
t_f  = d / (v₀ cosθ)
```

提前量迭代（照参考 `resolve_aim_time`）：用 `t_f` 把目标预测到 `t + t_f`，
重算 `t_f`，直到 `|Δ t_f| < 1 ms` 或迭代 5 次。

**验收数字**：
- 静态目标：连续 20 帧 `pitch` 标准差 ≤ 0.05°
- 运动目标：提前量迭代 3 次内收敛（`|Δt_f| < 1 ms`）
- 云台到位后（`gimbal_link` 真值 vs 指令）残差 ≤ 0.2°

**失败分叉**：
- 静态目标 pitch 抖 → 回到 P6，是瞄准面在跳
- 提前量不收敛 → `v₀` 或距离取值错；先量 `dist` 与真值的差
- 云台残差大 → 查 `from_solver_degrees` 的角度约定（`pitch_deg − 180°`），不要改视觉侧

## 5. 顺序为什么不能换

1. **P1 在 P2 之前**：PnP 是纯相机系计算，不依赖 TF；先用真值把解算本身钉死，后面帧变换错了才能立刻归因。
2. **P2 在 P3 之前**：姿态滞后 30 ms 就是 12.7°，它会让观测残差整体变大；不先消掉它，P3 的 NIS 分不清是"模型错"还是"输入错"。
3. **P3 在 P4 之前**：先知道残差与假设噪声的比例，P4 放宽 P0 之后才能判断 NIS 的变化是"更自洽"还是"更松"。
4. **P4 在 P5 之前**：ω 收敛不了时，面序必然乱；先让 ω 跟得上，再谈面序稳定，否则会把 P4 的问题记到 P5 头上。
5. **P5 在 P6 之前**：P5 管的是"状态别被单板帧拽偏"，P6 管的是"打哪一面"；状态先稳，瞄准面的判据才有意义。
6. **P6 在 P7 之前**：提前量要预测到 `t + t_f`，前提是状态本身准；瞄准面还在跳的时候加提前量，等于把噪声放大。
